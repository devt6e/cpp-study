## 🌅 오전: 추상 클래스 & 인터페이스

### 핵심 개념

**순수 가상함수 (`= 0`)**
- 구현이 없는 가상함수. "이 함수는 자식이 반드시 구현해야 한다"는 강제 계약
- `= 0`은 클래스 전체가 아니라 **그 함수 하나에만** 붙는 표식
- 미구현 순수 가상함수가 하나라도 남아있으면 그 클래스는 인스턴스화 불가 (추상 클래스)

**추상 클래스 vs 인터페이스**
| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 관계 | "~이다" (is-a) | "~할 수 있다" (can-do) |
| 내용 | 순수 가상함수 + 일반 함수/멤버 변수 혼합 가능 | 순수 가상함수만, 멤버 변수 없음 |
| 목적 | 공통 로직/상태 공유 + 일부 기능 강제 | 오직 기능 강제(계약)만 |
| 다중 상속 | 잘 안 씀 (다이아몬드 문제) | 여러 개 동시 구현 흔함 |

**가상 소멸자가 필요한 정확한 조건**
- "추상 클래스라서"가 아니라 **"부모 포인터로 `delete`할 때"** 필요
- `delete e;`는 사실 `e->~Enemy()` 함수 호출과 같음 → virtual 없으면 컴파일 타임에 선언 타입(`Enemy`) 기준으로 소멸자가 결정되어 자식 소멸자가 스킵됨 (자원 누수)
- 추상 클래스는 애초에 다형적으로 쓰일 확률이 매우 높아서 관례적으로 항상 가상 소멸자를 넣음

**vtable은 이름이 아니라 슬롯(인덱스)로 관리됨**
- 컴파일 타임에 클래스별로 "몇 번째 슬롯에 어떤 함수가 들어갈지" 레이아웃이 정해짐
- 소멸자(`~Enemy()`, `~Dragon()`)도 이름은 다르지만 "소멸자 슬롯"이라는 정해진 위치에 각자 등록됨
- 런타임엔 이름이 아니라 "vptr → N번 슬롯 함수 호출"만 일어남

### 코드 예시

```cpp
// 추상 클래스: 공통 로직 + 강제 기능 혼합
class Enemy {
public:
    virtual void Attack() = 0;                     // 순수 가상함수 (강제)
    void Patrol() { std::cout << "patrolling\n"; }  // 일반 함수 (공유 로직)
    int GetHealth() { return health; }
    virtual ~Enemy() {}                              // 가상 소멸자 필수
protected:
    int health = 100;
};

// 순수 인터페이스: 계약만
class IDamageable {
public:
    virtual void TakeDamage(int amount) = 0;
    virtual ~IDamageable() {}
};

class IInteractable {
public:
    virtual void OnInteract() = 0;
    virtual ~IInteractable() {}
};

// 다중 상속으로 여러 인터페이스 조합
class Barrel : public IDamageable, public IInteractable {
public:
    void TakeDamage(int amount) override { /* 폭발 */ }
    void OnInteract() override { /* 흔들림 */ }
};
```

### 주의사항

- `override` 키워드 없이 시그니처를 실수하면(타입 오타 등) 오버로딩으로 취급되어 **소리 없는 버그** 발생 → 항상 `override` 명시
- `new`한 객체는 반드시 `delete` 짝을 맞출 것 (1번 연습문제에서 실제로 누수 발견됨)
- 다중 상속 시 인터페이스 포인터로 업캐스팅하면 컴파일러가 내부적으로 포인터 주소를 조정함 (오프셋 차이)

## 📝 오늘 작성한 프롬프트 & 피드백

### 추상 클래스 3번 문제 답변 프롬프트
> "추상 클래스는 공통 기능의 상속에 초점을 두고 특정 기능을 강제하기 위해 디자인 됐기 때문이다. 인터페이스는 특정 기능을 강제하것만을 위해 디자인 되어 차이점이 있다."

**피드백**: 추상 클래스와 인터페이스의 목적 차이는 정확히 짚었지만, 문제가 실제로 물어본 **"왜 컴파일이 가능한가(메커니즘)"**에 대한 답이 빠져 있었음. 개념 비교와 메커니즘 설명은 서로 다른 질문이니, 문제에 여러 개의 질문이 섞여 있을 때는 각각을 빠짐없이 짚는 습관을 들이면 좋음.
